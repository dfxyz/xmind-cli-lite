# Recipe: 方案对比与决策

适用：技术选型、供应商对比、路线取舍。

## 骨架

默认 `mindmap`；只做二维对照时可试 `matrix` 或 `grid`，但先在 Desktop 看效果。

## 草稿

```markdown
# 选型：X vs Y

## 评估维度

- 成本
- 性能
- 维护
- 迁移风险

## 方案 A

### 成本
- 低
### 性能
- 中
### 风险
- 供应商锁定

## 方案 B

### 成本
- 中
### 性能
- 高
### 风险
- 迁移工作量大

## 结论

- 推荐 B
```

## 补充结论结构

```json
[
  {"op":"boundary","parent":{"path":["结论"]},"range":[0,0],"title":"决策"},
  {"op":"summary","parent":{"path":["评估维度"]},"range":[0,3],"text":"性能优先"},
  {"op":"relationship","from":{"path":["方案 B","风险"]},"to":{"path":["结论"]},"label":"需缓解"}
]
```

## 约束

- 维度先定，再填方案；不要按方案列维度。
- 结论分支必须有明确选择和一句理由。
- 对比项用相同粒度；缺失信息写“未知”，不要留空节点。
- 不把整段论证塞进标题；理由放备注。
